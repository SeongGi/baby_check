# 01-요구사항: Cloudflare Workers 기반 무과금 데이터 동기화 전환

## 1. 배경 및 목표
* **배경**: 
  * 현재 Firebase Firestore 기반 동기화는 소규모 가족 테스트에는 적합하나, 공개 배포 시 일일 무료 읽기/쓰기 한도(5만/2만 회) 초과로 인한 요금 과금 위험이 큼.
  * P2P(휴대폰 간 직접 통신)는 모바일 OS의 백그라운드 절전 정책 및 원격 부모(회사-집) 간 공유 불가 문제로 육아 앱에 부적합함.
* **목표**: 
  * 일일 10만 회 무료 요청이 제공되는 **Cloudflare Workers + D1(또는 KV)** 백엔드로 동기화 시스템을 전면 전환.
  * 수백~수천 가족이 사용하여도 **서버 비용 0원(무료)**을 유지하고, Firebase SDK 의존성을 걷어내어 앱을 경량화.
  * 기존 부모 사용자의 동기화 경험(초대 링크, 증분 동기화, 오프라인 우선 보존, 가족 삭제)을 100% 동일하게 유지.

## 2. 하지 않을 것 (Non-goals)
* 블루투스/로컬 Wi-Fi 기반 P2P 실시간 통신 (원격 동기화 불가 및 백그라운드 소켓 단절 문제로 제외).
* 기존 사용자 UI/UX 변경:
  * 가족 초대 링크 형식(`babycheck://family/[32자키]`), '지금 동기화', '새 가족 연결 만들기' 등 사용자 화면 및 워크플로는 완전히 동일하게 유지.
* 기존 로컬 저장소 스키마 파괴:
  * AsyncStorage에 저장된 `baby_check_logs`, `baby_check_profile`, `baby_check_sync_ledger` 등 기존 육아 데이터 구조를 보존하여 업데이트 시 데이터 유실 방지.

## 3. 성공 기준 (Acceptance Criteria)
1. **Cloudflare Worker 백엔드 (`server/` 또는 `backend/`) 완성**:
   * D1 SQLite 기반 스키마 (families, members, logs, deletion_schedule).
   * REST API 엔드포인트:
     * `POST /api/family/connect`: 가족 존재 확인 및 회원 등록/신규 생성.
     * `GET /api/family/token`: 최신 변경 토큰(해시/타임스탬프) 조회 (초경량 폴링용).
     * `POST /api/family/sync`: 증분 푸시 및 풀 (추가/수정/삭제 전파).
     * `POST /api/family/delete-schedule`, `POST /api/family/cancel-delete`: 가족 삭제 예약 및 취소.
     * `POST /api/family/delete`: 냉각 기간 후 영구 삭제.
2. **모바일 앱 클라이언트 연동**:
   * `src/database/sync.ts`의 Firebase 호출 로직을 Cloudflare REST API 클라이언트로 교체.
   * `syncWithCloud`, `subscribeToCloudChanges`, `readFamilyChangeToken`, `deleteFamilyData` 등 기존 앱 인터페이스 100% 호환.
   * 오프라인 시 로컬 저장 및 네트워크 복구 시 자동 재시도 로직 유지.
3. **무결성 및 테스트 검증**:
   * `tools/sync-harness/verify.sh offline` 전체 통과 (동기화 하네스 스텁/테스트 호환성 유지).
   * `npx tsc --noEmit` 타입 검사 통과.
   * 기존 음성 테스트(`tests/voice*.mjs`) 등 회귀 테스트 통과.
4. **배포 준비 및 문서화**:
   * `wrangler.toml` 및 배포 가이드 완비.
   * 원클릭 배포 명령어 제공.

## 4. 운영 위험 및 대응
* **위험 1: Cloudflare Worker 배포 인증**
  * 사용자의 Cloudflare 무료 계정 연동 필요 (`wrangler login` 1회 터미널 브라우저 인증).
  * 대응: 터미널에서 `npx wrangler login` 실행 시 URL 제공 및 원클릭 인증 가이드.
* **위험 2: 실시간 수신 방식 변화**
  * Firestore의 WebSocket `onSnapshot` 대신 Cloudflare 환경에서의 변경 감지.
  * 대응: 배터리와 무료 요청 한도(일일 10만 회)를 보호하기 위해, 상시 소켓 대신 앱 포그라운드 활성화 시(`AppState === 'active'`) 즉시 대조 + 활성 시 90초 주기 경량 토큰 대조(`GET /api/family/token`)로 구현하여 일 10만 회 쿼터를 수백~수천 가족이 안정적으로 공유할 수 있도록 함.

## 5. 열린 질문
* 백엔드 스토리지로 Cloudflare D1(관계형 SQLite) vs Cloudflare KV(키-값):
  * D1이 SQL 트랜잭션, 타임스탬프 기반 인덱싱, 증분 조회(`WHERE updatedAt > ?`)에 훨씬 적합하고 무료 티어(하루 읽기 500만 행, 쓰기 10만 행)가 압도적이므로 **D1** 채택.
