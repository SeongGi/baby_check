# Google 호출 후 음성 기록 설계

## 근거
- Google App Actions의 사용자 지정 명령과 OPEN_APP_FEATURE는 한국어 호출을 지원하지 않는다. 앱 열기는 일반 Assistant/Gemini 앱 열기 명령을 이용한다.
- 따라서 앱은 Google이 전달한 발화 전체를 받지 못한다. 앱이 전경으로 오면 기존 `expo-speech-recognition`을 시작한다.

## 흐름
사용자가 홈의 "앱을 열 때 바로 듣기"를 켬 → 로컬 AsyncStorage에 저장 → 앱이 새로 열리거나 백그라운드에서 복귀 → 홈의 VoiceLogButton에 한 번의 시작 요청 → 기기 한국어 인식 → 인식 결과 표시 → 사용자가 기록 확인.

## 상태와 예외
- MainApp이 자동 시작 설정 및 앱 전경 전환을 관리한다. 첫 실행은 설정·프로필 로드 후 별도 후보로 처리한다. 백그라운드에서 `active`로 돌아올 때마다 새 후보를 만든다.
- 후보는 홈 화면에서 짧은 지연 후 한 번만 요청으로 바꾼다. 그 사이 딥링크·알림으로 다른 화면에 가면 후보를 폐기한다. 요청도 홈을 벗어나면 지운다. 이를 통해 음성 서비스의 오디오 포커스 반환 시간을 확보한다.
- 요청은 VoiceLogButton이 시작 직전에 소비한다. 홈 화면을 다시 방문할 때 반복하지 않는다.
- VoiceLogButton은 기존 수동 시작 함수를 재사용한다. 시작 중 중복 호출은 기존 가드로 차단한다.
- 앱이 홈 외 화면에 있을 때 전경 복귀하면 현재 화면을 유지하고 자동 시작하지 않는다.
- 권한 요청 중 홈을 떠나면 인식 시작을 취소하고, 듣는 중에 홈을 떠나면 인식을 중단한다.
- 권한 거부/음성 서비스 없음은 기존 안내를 쓴다. 설정 저장 실패는 값을 되돌린다.

## 독립 설계 검토
1차: 초기 실행 이벤트 누락, 딥링크·알림과 경합, 오디오 포커스, 언마운트 뒤 인식 시작 위험 지적. 위 상태와 예외 항목에 반영. 2차 독립 재검토 승인.
