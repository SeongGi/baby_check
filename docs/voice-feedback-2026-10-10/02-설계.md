# 설계

1. 음성 입력 화면 상태를 `idle → starting → listening → processing → ready/error`로 명시한다. 버튼을 누르면 네이티브 호출 전에 `starting`을 표시한다.
2. 권한은 `getPermissionsAsync()`로 먼저 읽고, 미허용일 때만 `requestPermissionsAsync()`를 호출한다. 권한 화면 복귀는 같은 시도를 계속 처리한다.
3. 인식 이벤트 `start`는 `listening`, 최종 `result`는 전사와 파싱 결과를 즉시 보관하면서 `processing`을 표시한다. 짧은 렌더 기회 뒤 `ready`로 전환한다. 앱이 잠시 뒤로 가도 이미 인식한 명령은 잃지 않는다.
4. 네이티브 이벤트에는 시도 ID가 없으므로 인식 세션을 직렬화한다. `end`가 올 때까지 새 `start`를 호출하지 않으며, 시작 버튼은 중복 시도를 막는다. 권한 확인 중에는 아직 네이티브 세션이 없으므로 로컬 세대 번호로 이전 비동기 결과를 버린다.
5. 설치된 Android 인식 라이브러리는 최종 `result` 후 `end`를 보낸다. 최종 결과를 받으면 처리 결과를 유지하고, 이후 `end`는 듣기 표시만 정리한다. `end`가 먼저 오면 무음 종료로 처리하고 이후 늦은 `result`는 버린다. 오류 뒤 늦은 결과도 버린다.
6. 자동 취소·무음·권한 거부에도 사용자가 다음 행동을 알 수 있는 문구를 표시한다.
   Android는 실시간 상태 영역으로, iOS는 VoiceOver 알림으로 상태 전환을 알린다.
7. 앱이 실제로 백그라운드로 나간 경우 인식을 중단한다. 일시적인 `inactive`는 시스템 권한·인식 UI 전환일 수 있으므로 즉시 중단하지 않는다.

## 검토할 쟁점
- 네이티브 이벤트에는 식별자가 없으므로 이전 세션 `end`가 오기 전 새 세션을 열지 않는다.
- 사용자가 취소하거나 화면을 떠난 뒤 늦게 도착한 전사는 버린다.
