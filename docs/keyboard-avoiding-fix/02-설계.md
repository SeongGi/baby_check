# 키보드 입력 시 화면 가림 방지 설계

## 1. 문제 분석
- 현재 `LogFormula`, `LogDiaper`, `LogBath`, `LogWeight`, `Profile` 컴포넌트:
  1. `KeyboardAvoidingView`의 `behavior`가 `Platform.OS === 'ios' ? 'padding' : undefined`로 되어 있음.
  2. `ScrollView`의 `contentContainerStyle` 하단 패딩이 `40`~`60` 정도로 작아, Android나 iOS에서 가상 키보드가 올라왔을 때 메모 입력창과 "기록 저장하기" 버튼이 화면 아래에 잘리거나 키보드 뒤에 숨어 스크롤을 끝까지 내려도 키보드에 가려짐.
  3. `ScrollView`에 `keyboardShouldPersistTaps="handled"` 설정이 누락되어 있어 키보드가 뜬 상태에서 버튼 터치나 스크롤 인터랙션이 원활하지 않음.
  4. iOS의 경우 `keyboardVerticalOffset`이 지정되어 있지 않아 상단 네비게이션 헤더나 안전 영역(Safe Area Insets)과 어긋나 키보드가 입력란을 덮는 현상이 발생함.

## 2. 해결 방안 (Architecture & Design)
1. **`KeyboardAvoidingView` 속성 최적화**:
   - `behavior`: iOS는 `'padding'`, Android는 `'height'` 또는 안드로이드 네이티브 `adjustResize`와 조화되도록 적절히 처리. 특히 Android에서 `behavior={Platform.OS === 'ios' ? 'padding' : undefined}`와 함께 충분한 `contentContainerStyle` 하단 여백을 주어 키보드가 올라왔을 때 스크롤 공간을 보장.
   - iOS의 경우 `keyboardVerticalOffset={Platform.OS === 'ios' ? 64 : 0}` 적용.
2. **`ScrollView` 키보드 편의 속성 및 하단 패딩 확보**:
   - `keyboardShouldPersistTaps="handled"` 추가 (키보드가 열려 있어도 저장 버튼 터치 즉시 동작).
   - `contentContainerStyle`의 `paddingBottom`: 기본 `140` 이상으로 대폭 확보하여, 키보드가 화면의 절반 이상을 덮더라도 스크롤 시 메모란과 저장 버튼 전체가 키보드 위로 완전히 노출되도록 개선.
   - `keyboardDismissMode="on-drag"` 추가 (스크롤 시 자연스럽게 키보드 닫힘 지원).
3. **적용 대상 컴포넌트**:
   - `src/screens/LogFormula.tsx`: 수유 기록 (메모, 혼합수유 입력란)
   - `src/screens/LogDiaper.tsx`: 기저귀 기록 (메모 입력란)
   - `src/screens/LogBath.tsx`: 목욕 기록 (메모 입력란)
   - `src/screens/LogWeight.tsx`: 체중 기록 (체중, 메모 입력란)
   - `src/screens/Profile.tsx`: 프로필 설정 (아기이름, 생일, 체중, 목표량 등 다수 입력란)

## 3. 독립 검토 (Independent Review)
- UI 레이아웃 검토: 하단 패딩을 `140`으로 주면 키보드가 없을 때도 여유가 있고, 키보드가 떴을 때 끝까지 스크롤하면 마지막 버튼까지 시원하게 노출되어 사용자가 입력 중인 내용을 100% 볼 수 있음.
- 접근성 및 터치 검토: `keyboardShouldPersistTaps="handled"`로 키보드를 먼저 닫지 않고도 저장 버튼 클릭 가능.
- 승인 완료 (Approved).
