# 03. 커밋 단위 계획: 한줄 육아일기와 댓글

설계는 `02-설계.md`를 따른다. 커밋마다 `npx tsc --noEmit`이 통과해야 다음 커밋으로 넘어간다.

| 순서 | 커밋 | 바꾸는 파일 | 커밋 전 확인 |
|---|---|---|---|
| 1 | 데이터 모양과 순수 함수 | `src/types.ts`(DiaryRole, DiaryLog, DiaryCommentLog, `isDiaryType`, `BabyProfile.diaryRole`), 새 `src/utils/diary.ts`(`pickDiaryLine`, `groupDiaryByDate`, `diaryGroupLines`, `countCodePoints`, `toDiaryDate`, `makeDiaryId`) | tsc, 2번 커밋의 시험 중 순수 함수 부분 |
| 2 | 저장 함수와 역할 보존 | `src/database/storage.ts`(`saveDiaryLine`, `deleteDiaryGroup`, `normalizeProfile`의 역할 정리, `importDataWithoutLoss`·`restoreFromLocalBackup`의 역할 유지), 새 `tools/sync-harness/diary-unit.mjs`(하네스 로더의 파일 저장소 흉내로 실행), `verify.sh`에 `diary` 모드 추가와 `offline`에 포함, `package.json`에 `test:diary` | `npm run test:diary`, tsc |
| 3 | 기존 화면에서 일기 거르기 | `Dashboard.tsx` 타임라인(`activityLogs`), `Statistics.tsx`, `feedingReminder.ts` | tsc, `test:diary`의 거르기 시험, `npm run test:voice` |
| 4 | 프로필 "일기 작성자" | `Profile.tsx` | tsc |
| 5 | 입력 창과 일기 화면, 홈 칸 | 새 `src/components/DiaryEditor.tsx`, 새 `src/screens/Diary.tsx`, `Dashboard.tsx`(오늘의 한 줄 칸), `App.tsx`(`'diary'` 화면, `handleSaveDiaryLine`, `handleDeleteDiaryGroup`) | tsc |
| 6 | 두 기기 하네스 시나리오 | `tools/sync-harness/` 시나리오 추가 | `verify.sh offline`, `verify.sh real` |
| 7 | 검증 문서 | `docs/daily-diary/04-검증.md` | 전체 검사, 변이 검증 결과 기록 |

## 위임
- 1~6번은 여러 파일에 걸친 구현이므로 t1-worker(sonnet, effort high)에 넘긴다. 설계가 정해져 있고 시험과 tsc로 틀리면 바로 드러나는 일이라 이 단계가 맞다.
- 메인 세션은 돌려받은 diff와 실제 시험 출력을 확인한 뒤 독립 리뷰 2개(정확성·데이터 보전 / 화면·1.8.0 호환)를 띄운다.
