# 01-요구사항: 상대 기기 기록 알림

- 요청: 2026-10-30, 성기님 ("내 기기에서 기록하면 상대방 기기에도 알림이 가도록")
- 출시: 1.8.0 다음 버전(1.8.1 예정). 1.8.0(Cloudflare 동기화 전환)이 출시된 뒤에 시작한다.
- 전제: 가족 동기화가 Cloudflare Worker + D1(`docs/cloudflare-sync-migration/`)로 옮겨진 상태

## 1. 목표
가족으로 연결된 한 기기에서 기록을 남기면, 같은 가족의 다른 기기에 몇 초 안에 알림이 뜬다. 상대 기기의 앱이 꺼져 있어도 알림이 온다.

## 2. 결정 사항 (성기님 답변)
| 항목 | 결정 |
|---|---|
| 전달 방식 | 서버 푸시. 동기화 Worker가 기록을 받으면 Expo 푸시 서비스로 상대 기기에 보낸다. |
| 알림 대상 | 기록 종류별로 켜고 끈다. 처음에는 모두 켜 둔다. |
| 출시 범위 | 1.8.0 다음 버전 |

## 3. 기능 요구사항
1. **보내는 조건:** 동기화 요청(`POST /api/family/sync`)으로 새 기록이 D1에 처음 들어오면, 같은 가족의 다른 기기에 알림을 보낸다.
   - 보낸 기기 자신에게는 보내지 않는다.
   - 수정과 삭제에는 보내지 않는다. 처음 생긴 기록만 대상이다.
   - 이전(05 설계의 첫 업로드), 전체 대조, 백업 복원처럼 옛 기록을 한꺼번에 올리는 경우에는 보내지 않는다. 기준은 기록 시각이 지금부터 일정 시간(초안: 30분) 안인 기록만 알리는 것이다.
2. **기록 종류별 설정:** 받는 기기가 설정 화면에서 아래 9종을 각각 켜고 끈다. 처음에는 모두 켠다. 전체 끄기도 둔다.
   - 분유·수유(`formula`), 소변(`urine`), 대변(`stool`), 목욕(`bath`), 체중(`weight`), 체온(`temperature`), 수면(`sleep`), 터미타임(`tummyTime`), 놀이(`play`)
   - 설정은 받는 기기마다 따로 둔다. 서버는 받는 기기의 설정을 보고 보낼지 정한다.
3. **묶어 보내기:** 한 번의 동기화로 새 기록이 여러 개 들어오면 알림 하나로 묶는다(예: "분유 외 2건").
4. **알림 내용:** 기록 종류와 시각을 보여 준다. 알림을 누르면 앱이 열리고 해당 기록이 있는 화면으로 간다.
5. **권한:** 알림 권한이 없으면 설정 화면에서 권한을 요청한다. 거부하면 서버에 토큰을 등록하지 않는다.
6. **토큰 관리:** 기기는 Expo 푸시 토큰을 서버에 등록한다. 가족 연결 해제, 가족 영구 삭제, 알림 전체 끄기 때 토큰을 지운다. Expo가 `DeviceNotRegistered`를 돌려주면 서버가 그 토큰을 지운다.
7. **혼자 쓰기:** 가족 연결이 없으면 토큰을 등록하지 않고 푸시 관련 요청을 보내지 않는다.

## 4. 비기능 요구사항
- **동기화 보호:** 푸시 발송이 실패하거나 느려도 동기화 응답과 기록 저장에는 영향이 없어야 한다. Worker는 응답을 먼저 돌려주고 발송은 `ctx.waitUntil`로 처리한다.
- **비용:** Expo 푸시 서비스는 무료다. Worker 요청 수와 D1 읽기는 동기화 1회당 몇 건 늘어나는 수준이어야 한다.
- **개인정보:** 알림 내용은 Expo와 Google(FCM) 서버를 거친다. 초안에서는 알림에 기록 종류와 시각만 담고, 분유량이나 체온 같은 수치는 담지 않는다. 개인정보처리방침과 Play 데이터 보안 항목에 푸시 토큰 수집을 추가한다.
- **플랫폼:** Android(Play, 원스토어)만 대상이다. iOS는 출시하지 않으므로 다루지 않는다.

## 5. 성기님이 해야 하는 외부 설정 (구현 전 승인 필요)
서버 푸시를 쓰려면 아래 작업이 한 번 필요하다. 구현 단계에서 순서를 안내하고, 각 작업 전에 확인을 받는다.

1. Firebase 콘솔(`babycheck-sync` 프로젝트)에 Android 앱(`com.seonggi.babycheck`)을 등록하고 `google-services.json`을 받는다.
2. FCM V1 서비스 계정 키를 만들어 EAS(`eas credentials`)에 올린다. Expo 푸시가 Android로 보낼 때 이 키를 쓴다.
3. 원스토어 빌드도 같은 패키지 이름이므로 같은 설정을 쓴다. 이 점은 구현 단계에서 확인한다.

## 6. 정하지 않은 것 (설계 단계에서 제안하고 확인받는다)
- 밤 시간 무음 같은 방해 금지 시간대를 둘지
- 알림에 기록한 사람 이름("엄마가", "아빠가")을 넣을지. 지금은 기기 이름이 없다.
- "옛 기록" 기준 시간 30분이 적절한지
- 수치를 알림에 넣는 선택 설정을 둘지

## 7. 완료 기준
- 두 기기(에뮬레이터 두 대 또는 실기기)에서 A가 기록하면 앱이 꺼진 B에 10초 안에 알림이 뜬다.
- B가 끈 종류의 기록은 알림이 오지 않는다.
- 이전, 전체 대조, 백업 복원 때 알림이 쏟아지지 않는다.
- 푸시 서버가 실패해도 동기화 하네스(`verify.sh offline`)가 그대로 통과한다.
- 혼자 쓰는 기기의 푸시 관련 요청은 0회다.
