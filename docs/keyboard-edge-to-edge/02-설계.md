# 1.7.9 설계

## 1. 키보드 가림 원인
- `android/gradle.properties`의 `edgeToEdgeEnabled=true`이고 RN 0.85는 edge-to-edge가 기본이다. 이 상태에서는 `windowSoftInputMode="adjustResize"`가 창을 줄이지 않는다.
- 그런데 1.7.8은 Android에서 `KeyboardAvoidingView`의 `behavior`를 `undefined`로 두어 OS의 창 축소에 맡겼다. 결국 아무것도 화면을 줄이지 않아 키보드가 입력창을 덮었다. 하단 여백 140은 끝까지 스크롤할 공간만 만들 뿐, 초점을 받은 입력창을 키보드 위로 올리지 않는다.
- RN의 `KeyboardAvoidingView`는 `onLayout`의 부모 기준 좌표와 키보드의 화면 기준 좌표를 비교한다. 이 앱은 상단 안전 영역과 배너 아래에 화면을 두므로 그 차이만큼 덜 올린다. iOS에 고정값 64를 넣었던 이유도 이것이다.
- ScrollView 내장 함수 `scrollResponderScrollNativeHandleToKeyboard`도 ScrollView가 화면 맨 위에 있다고 가정하므로 쓰지 않는다.

## 2. 해결
- `src/components/KeyboardAwareScrollView.tsx`를 새로 만든다.
  - 키보드가 뜨면 바깥 View를 `measureInWindow`로 재서, 키보드가 덮는 높이만큼 `paddingBottom`을 준다. 창 기준 좌표끼리 비교하므로 플랫폼별 고정값이 필요 없다.
  - 여백이 반영되어 레이아웃이 바뀌면 초점을 받은 입력창(`TextInput.State.currentlyFocusedInput()`)을 다시 재고, 키보드 위 24px 안에 들어오도록 그만큼 스크롤한다.
  - OS가 창을 실제로 줄이는 기기에서도 다시 잰 값이 0이 되므로 여백이 두 번 들어가지 않는다.
- 분유·기저귀·목욕·체중·체온·설정 화면은 `KeyboardAvoidingView + ScrollView`를 이 컴포넌트로 바꾼다.
- 홈의 기록 수정 모달과 다음 수유 시간 모달은 창 맨 위에서 시작하므로 `KeyboardAvoidingView behavior="padding"`을 두 플랫폼 모두에 쓴다. 수정 모달 안쪽 ScrollView는 위 컴포넌트로 바꿔 초점을 받은 입력창까지 스크롤한다.

## 3. 체온 기록
- `type: 'temperature'`, 값은 `temperatureC`(℃, 소수 첫째 자리)다. 분유 온도 필드 `temperature`와 헷갈리지 않게 이름을 달리했다.
- 체중 기록과 같은 구조로 입력 화면, 홈 빠른 기록 버튼, 목록 표시, 수정 모달, 통계(최근 체온, 기간 내 최고 체온)를 추가한다.
- 유효 범위는 34~42℃다. 38℃ 이상이면 "아기 상태를 잘 살펴 주세요" 안내만 보여 주고, 진단처럼 들리는 문구는 넣지 않는다.
- 동기화는 기록 객체를 통째로 보내므로 동기화 코드 변경이 필요 없다.

## 4. 원스토어
- 빌드할 때 `EXPO_PUBLIC_DISTRIBUTION_STORE=onestore`를 넣으면, 설정 화면의 "Google Play에서 업데이트 확인" 버튼 대신 원스토어 안내 문구를 보여 준다.
- 원스토어 상품 ID는 등록이 끝나야 나오고 딥링크 형식도 확인하지 못했으므로, 링크는 등록 후 추가한다.
- 등록 절차와 서명 주의 사항은 `docs/ONESTORE_RELEASE.md`에 정리한다.

## 5. 독립 검토
- 검토 관점: 이중 여백, 모달 안 높이 0, 입력창 사이 초점 이동, 구버전 호환성.
- 모달처럼 높이가 내용으로 정해지는 곳에서 `flex: 1`을 쓰면 높이가 0이 될 수 있다. 그래서 `containerStyle={{ flex: 0, flexShrink: 1 }}`로 덮어쓴다.
- 입력창 사이 초점 이동은 Android ScrollView의 `requestChildFocus`가 스크롤하고, 레이아웃이 바뀌면 컴포넌트가 다시 확인한다.
