# 앱 접근권한 사전 고지 (1.8.2): 설계

## 1. 순수 로직: `src/utils/permissionNotice.ts` (새 파일, React Native를 가져오지 않는다)
- `PERMISSION_NOTICE_KEY = '@babycheck/permissionNoticeSeen.v1'`
- `PERMISSION_NOTICE_ITEMS`: `{ name, required: false, reason }[]`
  - 마이크: "음성으로 수유·수면 등을 기록할 때 말소리를 인식합니다."
  - 알림: "다음 수유 시간이 되면 알려 드립니다."
- `shouldShowPermissionNotice(stored: string | null): boolean`: 저장값이 `'1'`이 아니면 true다.
- `shouldExplainBeforeRequest(p: { granted: boolean; canAskAgain?: boolean }): boolean`: 허용되지 않았고 `canAskAgain !== false`일 때 true다. 다시 물을 수 없는 상태면 허용 창이 뜨지 않으므로 안내도 띄우지 않는다.
- `MICROPHONE_PROMPT`, `NOTIFICATION_PROMPT`: `{ title, message }` 문구 상수. 메시지는 용도, 선택 권한이라는 점, 거부해도 다른 기능은 쓸 수 있다는 점을 담는다.
- `PERMISSION_NOTICE_TEXT`: 첫 실행 안내의 제목, 필수 권한 없음 문장, 맺음 문장("허용하지 않아도 다른 기능은 그대로 쓸 수 있습니다. 휴대폰 설정 > 애플리케이션 > 아기기록 > 권한에서 언제든 바꿀 수 있습니다.").

## 2. 사전 안내창: `src/utils/permissionPrompt.ts` (새 파일)
- `confirmPermissionPrompt(prompt): Promise<boolean>`: `Alert.alert(title, message, [{ text: '취소', style: 'cancel', onPress → false }, { text: '계속', onPress → true }], { cancelable: true, onDismiss → false })`. 한 번만 resolve되도록 막는다.
- 대기 중인 Promise를 모듈 수준에서 공유하지 않는다. 2차 검토 지적처럼 콜백 없이 사라진 Alert가 공유 항목으로 남으면 이후 시작이 모두 막히기 때문이다. 겹침 방지는 호출하는 쪽이 맡는다(4절, 5절).

## 3. 첫 실행 안내: `src/components/PermissionNoticeModal.tsx` (새 파일)
- `DiaryEditor`와 같은 `Modal transparent animationType="fade"` 형식이다. 항목 목록과 "확인" 버튼 하나만 둔다. 뒤로 가기(`onRequestClose`)도 확인과 같게 처리한다.
- `App.tsx`의 `MainApp`
  - 상태 `permissionNoticeVisible`(기본 false)와 `permissionNoticeReady`(기본 false)를 둔다. 이 상태와 저장값을 읽는 `useEffect`는 881행의 로딩 early return보다 **위**에 둔다(훅 순서 규칙).
  - 마운트 때 `AsyncStorage.getItem(PERMISSION_NOTICE_KEY)`를 읽어 표시 여부를 정하고 ready를 true로 둔다. 읽기에 실패하면 안내를 보여 준다.
  - 확인을 누르면 먼저 화면에서 닫고, `setItem(KEY, '1')`을 시도한다. 저장에 실패하면 다음 실행 때 다시 보이는 것으로 충분하다.
  - 음성 자동 시작 effect의 첫 조건에 `!permissionNoticeReady || permissionNoticeVisible`을 더해 return한다. 의존성 배열에도 두 값을 넣는다. 안내를 닫으면 effect가 다시 돌아 대기 중이던 자동 시작이 이어진다.
  - 모달은 `renderScreenContent()` 안이 아니라 본 화면 루트 `View`의 직속 자식으로 둔다. 위젯이나 알림으로 수유 화면에 바로 들어가도 안내가 사라지지 않게 하기 위해서다.
  - 앱 시작 때 뜨는 다른 Alert(백업 실패, 초대 결과, 연결 해제)가 모달과 겹치면 모달이 위에 보이고, 모달을 닫은 뒤 Alert가 보인다. 이 순서를 정상 동작으로 본다.

## 4. 마이크: `VoiceLogButton.tsx` 시작 함수
- `start(source: 'manual' | 'auto' = 'manual')`로 바꾼다. 자동 시작 effect(393행)는 `'auto'`, 버튼(416행)은 `'manual'`, 권한 화면 복귀 재개(376행)는 `'manual'`로 부른다.
- 새 ref 두 개를 둔다.
  - `explainPromptRef`: 안내창이 떠 있는 동안 true다.
  - `micNoticeDeclinedRef`: 이번 실행 중에 사용자가 안내창에서 취소했으면 true다.
- `start()` 맨 앞의 기존 조기 반환 조건에 `explainPromptRef.current`를 더한다. 안내창이 떠 있는 동안 들어온 시작은 새 안내창을 띄우지 않고 `'deferred'`로 끝난다.
- `getPermissionsAsync()` 뒤 `!permission.granted` 분기 안에서 `shouldExplainBeforeRequest(permission)`이면 다음 순서로 처리한다.
  1. `source === 'auto' && micNoticeDeclinedRef.current`이면 안내창을 띄우지 않고 아래 취소 처리로 바로 간다(앱을 열 때마다 안내창이 반복되는 것을 막는다).
  2. 아니면 `explainPromptRef.current = true` → `await confirmPermissionPrompt(MICROPHONE_PROMPT)` → `finally`에서 false로 되돌린다.
  3. 응답 직후 기존과 같은 `mounted / interrupted / generation` 검사를 한다. 걸리면 `'deferred'`로 끝낸다. 이때 `mounted.current && !starting.current && !nativeSessionOpenRef.current`이면, 즉 다른 시작이 진행 중이 아니면 `setPhase('idle')`, 상태 문구 "음성 버튼을 다시 눌러 주세요.", `onRecognitionActivity(false)`로 정리한다. 다른 시작이 진행 중이면 아무것도 바꾸지 않는다.
- 취소 처리: `micNoticeDeclinedRef.current = true`, 허용 창을 띄우지 않는다. 상태 문구는 "마이크 사용에 동의하지 않아 음성 기록을 시작하지 않았어요.", phase는 `'error'`, `starting.current = false`, `onRecognitionActivity(false)`, 반환값은 `'handled'`로 기존 거부 분기와 같다.
- "계속"을 고르면 `micNoticeDeclinedRef.current = false`로 두고 기존 흐름(`permissionPromptRef` 설정 → `requestPermissionsAsync`)을 그대로 탄다.
- AppState 처리(60~74행): 앱이 뒤로 갈 때 `explainPromptRef.current`가 true이면 기존 중단 처리(세대 증가, `starting=false`)에 더해 `explainPromptRef.current = false`, phase `'idle'`, 상태 문구 "음성 버튼을 다시 눌러 주세요."로 정리한다. Alert가 콜백 없이 사라져 묵은 `start`가 끝내 다음 단계로 진행하지 못해도 새 시작은 막히지 않는다. 앱으로 돌아와 묵은 안내창에서 "계속"을 누르면 세대 검사에 걸려 아무 일도 일어나지 않는데, 이것은 의도한 동작이다. 사용자는 문구대로 버튼을 다시 누르면 된다.

## 5. 알림: `feedingReminder.ts`
- 안내창을 수유 알림 처리 대기열(`reminderRefreshQueue`) **밖**에서 띄운다. 대기열 안에서 응답을 기다리면 그 뒤의 동기화 반영, 위젯 갱신, 알림 재예약이 모두 멈추기 때문이다.
- `refreshFeedingReminder(logs, profile, askPermission)`에서 `askPermission`이 true이면 대기열에 넣기 전에 `ensureFeedingReminderPermission()`을 먼저 await한다. 이 함수는 채널을 만들고 현재 권한을 읽는다. 허용돼 있으면 true를 돌려준다. `shouldExplainBeforeRequest`가 true이면 `confirmPermissionPrompt(NOTIFICATION_PROMPT)`를 띄우고, 취소하면 false를 돌려준다. "계속"이면 `requestPermissionsAsync`를 부른다.
- 그 뒤 대기열 작업은 `askPermission = false`로 실행해 허용 여부만 확인한다. 따라서 다음 수유 시간이 없어도 알림을 켜는 순간 권한을 묻는다.
- 권한을 기다리는 사이 다른 갱신이 먼저 대기열에 들어갈 수 있다. 그래서 이 경로의 대기열 작업은 넘겨받은 `profile` 대신 저장소의 최신 프로필(`getProfile()`)과 넘겨받은 `logs`로 실행한다. `feedingReminder.ts`가 저장소 모듈을 가져올 때 순환 참조가 생기면, App.tsx에서 `ensure` 뒤에 최신 프로필을 읽어 `refreshFeedingReminder`를 부르는 방식으로 바꾼다.
- `ensure`가 false여도(취소나 거부) 대기열 작업(기존 예약 취소, 위젯 갱신)은 그대로 실행하고, `refreshFeedingReminder`는 false를 돌려준다.
- 알림 안내창은 대기열 밖에 있으므로 응답이 없어도 그 호출 하나만 멈춘다. 모듈 수준 `notificationPromptPending` 플래그를 두어, 안내창이 떠 있는 동안 들어온 두 번째 요청에는 안내창 없이 현재 허용 여부만 돌려준다. 앱이 뒤로 갈 때 이 플래그를 지운다.
- 기존 `requestFeedingReminderPermission` export는 `ensureFeedingReminderPermission`으로 대체한다. 다른 호출처가 없다(`git grep`으로 확인).

## 6. 쓰지 않는 저장소 권한 제거
- `android/app/src/main/AndroidManifest.xml`의 `READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE`(maxSdk 32)는 Expo 기본 템플릿에서 온 것이고 코드에서 쓰지 않는다(파일 선택기나 미디어 라이브러리 의존성이 없다). 두 줄을 `tools:node="remove"` 선언으로 바꿔 라이브러리가 병합해 넣는 것도 막는다.
- `app.json`의 `android.blockedPermissions`에 같은 두 권한을 적어, 나중에 prebuild를 하더라도 되살아나지 않게 한다.

## 7. 개인정보처리방침
- `privacy-policy.html`에 "앱 접근권한" 절을 더한다. 필수 권한은 없고, 선택 권한은 마이크(음성 기록)와 알림(수유 알림)이며, 허용하지 않아도 다른 기능을 쓸 수 있고, 휴대폰 설정에서 바꿀 수 있다는 내용이다. 이 페이지는 GitHub Pages로 공개되므로 master에 머지돼야 반영된다.

## 8. 버전
- `app.json`(version, android.versionCode), `package.json`, `package-lock.json`의 앱 버전 2곳(3, 9행), `android/app/build.gradle`(versionCode, versionName)을 1.8.2 / 30으로 올린다. `package-lock.json`의 `etag` 1.8.1과 `tools/rules-check/package-lock.json`은 앱 버전이 아니므로 건드리지 않는다.

## 고려한 대안
- 원스토어 전용 빌드에서 마이크를 빼는 방법: 빌드를 둘로 나누어 출시 비용이 두 배가 되고, Play의 한국 사용자에게도 같은 법이 적용되므로 버렸다.
- 첫 실행 안내만 두는 방법: 공지가 요구하는 "요청 시점의 이유 고지"를 기능 사용 순간에 다시 보장하려고 요청 직전 안내창도 둔다.
