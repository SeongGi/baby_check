# 앱 접근권한 사전 고지 (1.8.2): 요구사항

## 배경
- 원스토어가 2026-11-02에 1.8.1(코드 29)의 검증을 승인했다(14:21:42, 상태 "판매대기"). 같은 날 "앱 접근권한 관련 법규 준수 요청" 메일도 보냈다. 메일 내용은 마이크 권한을 요구하면서 이용자에게 사전 고지와 동의 절차가 없다는 것이다.
- 근거는 정보통신망법 제22조의2와 방송통신위원회 「스마트폰 앱 접근권한 개인정보보호 안내서」다. 원스토어 공지(noticeId 29422)가 정리한 요점은 세 가지다.
  1. 접근권한을 필수와 선택으로 구분한다.
  2. 접근이 필요한 항목과 그 이유를 이용자에게 명확하게 고지한다.
  3. 접근권한에 대해 이용자의 동의를 받는다.
- 이 법은 한국 이용자 모두에게 적용되므로, Play와 원스토어에 같은 빌드를 낸다(성기님 결정: 원스토어에서만 마이크를 빼지 않는다).

## 실행 중에 요청하는 권한 (현재 코드 기준)
| 권한 | 요청 위치 | 구분 | 용도 |
|---|---|---|---|
| 마이크(`RECORD_AUDIO`) | `src/components/VoiceLogButton.tsx` 음성 기록 시작 | 선택 | 말로 수유·수면 등을 기록할 때 음성을 인식한다 |
| 알림(`POST_NOTIFICATIONS`, Android 13 이상) | `src/utils/feedingReminder.ts` 수유 알림을 켤 때 | 선택 | 다음 수유 시간을 알린다 |

필수 권한은 없다. 인터넷과 진동은 설치 때 자동으로 허용되는 권한이다. Android 12 이하용 저장소 권한(`READ/WRITE_EXTERNAL_STORAGE`)은 Expo 기본 템플릿이 넣은 것이고 코드에서 쓰지 않으므로 이번에 제거한다.

## 목표
1. 앱을 처음 실행하면(1.8.2로 업데이트한 기존 사용자 포함) 접근권한 안내를 한 번 보여 준다. 안내에는 필수 권한이 없다는 것, 선택 권한 2개의 이름과 이유, 허용하지 않아도 나머지 기능을 쓸 수 있다는 것, 나중에 바꾸는 방법을 적는다.
2. 마이크와 알림 권한은 운영체제 허용 창을 띄우기 직전에 앱이 먼저 짧은 안내창을 보여 주고, 사용자가 "계속"을 고를 때만 허용 창을 연다.
3. 쓰지 않는 저장소 권한을 제거하고, 개인정보처리방침에 접근권한 절을 더한다.
4. 버전을 1.8.2(코드 30)로 올린다.

## 하지 않을 것
- 원스토어 전용 빌드나 기능 제거
- 권한 설정 화면, 설정 탭 안의 안내 다시 보기 메뉴
- 빌드, 스토어 제출, 원스토어 1.8.1 "적용하기"(모두 성기님 승인 뒤 별도 진행)
- `expo prebuild`, `expo run:android` 실행

## 성공 기준
- 새로 설치했을 때와 업데이트했을 때 모두 첫 화면에서 안내가 한 번만 뜨고, 확인 뒤에는 다시 뜨지 않는다.
- 안내가 떠 있는 동안 "앱 열 때 음성 기록 자동 시작"이 마이크를 요청하지 않는다.
- 마이크 권한이 없는 상태에서 음성 버튼을 누르면 앱 안내창이 먼저 뜬다. "취소"를 고르면 허용 창이 뜨지 않고 음성 기록도 시작하지 않는다. 이미 허용한 기기에서는 안내창이 뜨지 않는다.
- 알림 권한이 없는 상태에서 수유 알림을 켜면 같은 순서로 동작한다. 다음 수유 시간이 아직 없어도 켜는 순간 묻는다.
- 안내창이 떠 있는 동안 앱을 뒤로 보냈다가 돌아와도 음성 버튼이 다시 눌린다. 음성 자동 시작을 켠 채 안내창에서 취소하면, 같은 실행 중에는 앱을 다시 열어도 안내창을 반복하지 않는다.
- `npx tsc --noEmit`, `npm run test:voice`, `npm run test:permission`이 통과한다.

## 운영 위험
- 실사용 가족 2명의 데이터: 저장소 키 하나만 새로 추가하고 기존 기록과 동기화 경로는 건드리지 않는다.
- 음성 자동 시작은 그동안 버그를 여러 번 고친 민감한 경로다. 안내창 때문에 시작 순서가 꼬이지 않아야 한다.

## 열린 질문
- 없음. 배포 옵션과 공개 시점은 빌드 뒤에 다시 여쭌다.
