# 점검 및 검증 결과

## 확인한 결함과 수정

- 수유 알림 갱신이 겹치면 예약이 중복될 수 있어 갱신 작업을 직렬화했다. 권한 요청도 대기 중 생략되지 않게 했다.
- 활동 버튼 연속 터치의 중복 저장을 막고, 기록 수정 저장이 실패하면 편집 내용을 유지하고 오류를 알리게 했다.
- 삭제한 기록을 백업 파일에서 가져올 때 기존 삭제 표식 때문에 복원되지 않던 문제를 수정했다. 복원 ID는 원본 기록 내용의 SHA-256으로 안정적으로 생성하며 기존 표식은 남긴다.
- 가족 서버 삭제 예약의 기한 검사와 앱 복귀 시 재검사를 추가했다. 서버 조회 실패를 예약 없음과 구분하고, 취소·삭제 경쟁을 막았다. 앱이 종료되어 있으면 자동 실행할 수 없는 실제 동작을 화면에 명시했다.

## 검사

- 기준 상태: `npx tsc --noEmit`, 음성 명령 8사례, 오프라인 동기화 검사 통과.
- 수정 후: `npx tsc --noEmit` 통과.
- `bash tools/sync-harness/verify.sh offline`: 48개 PASS. 기존 동기화 검사에 백업 복원 4개, 알림 갱신 2개 사례를 추가했다.
- `node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON tests/voiceCommand.mjs`: 8개 통과.
- `npx expo export --platform android --output-dir /tmp/baby-check-audit-export-final`: Android 번들 생성 통과.
- `git diff --check`: 통과.
- 안전한 임시 변이: 알림 갱신 큐를 일부러 비활성화하자 동시 갱신 검사에서 `2 !== 1`로 실패했다. 즉시 원복하고 검사를 다시 통과시켰다.
- 독립 코드 리뷰 2건을 최대 3회 진행했다. 처음 발견된 삭제 취소 경쟁, 권한 요청 생략, 타이머 등록 누락 등을 고쳤고 최종 리뷰에서 큰 지적은 없었다.

## 한계

- 실제 Android 기기에서 시스템 알림 권한과 가족 삭제 예약 화면을 확인하지 못했다.
- 실제 Firebase 데이터의 영구 삭제는 실행하지 않았다. 기존 오프라인 Firebase 모의 회귀 검사를 사용했다.
- 앱이 종료된 동안 가족 삭제를 서버가 자동 처리하는 기능은 없다. 기한 이후 앱의 설정 화면을 열고 연결되면 처리한다.
